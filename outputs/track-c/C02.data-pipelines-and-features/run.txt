== split_demo: random vs temporal vs grouped on identical data ==
dataset: 6000 rows, 600 users, 10 rows per user, base rate  0.4118 (seed 13)

features under test
  x_signal                 honest, stationary predictor
  x_drifting               predictive, but its relationship to the label flips over time
  x_user_mean_global       per-user label mean computed over ALL rows (leaks)
  x_user_mean_trainonly    per-user label mean fitted on TRAIN rows only

RANDOM split - rows shuffled; the same user and the same day appear on both sides
  train 4200 rows / test 1800 rows | test users also in train: 100% | time ranges overlap: yes
  base rate train  0.4079 vs test  0.4211
  feature                  test AUC
  x_signal                   0.7274
  x_drifting                 0.5080
  x_user_mean_global         0.7879
  x_user_mean_trainonly      0.6913

TEMPORAL split - train is the earlier period, test is the later period
  train 4200 rows / test 1800 rows | test users also in train: 100% | time ranges overlap: no
  base rate train  0.4117 vs test  0.4122
  feature                  test AUC
  x_signal                   0.6976
  x_drifting                 0.3310
  x_user_mean_global         0.7669
  x_user_mean_trainonly      0.6589

GROUPED split - train and test users are disjoint
  train 4200 rows / test 1800 rows | test users also in train: 0% | time ranges overlap: yes
  base rate train  0.4138 vs test  0.4072
  feature                  test AUC
  x_signal                   0.7001
  x_drifting                 0.5207
  x_user_mean_global         0.7949
  x_user_mean_trainonly      0.5000

measured optimism (random split test AUC minus the honest split's)
  feature                  vs grouped  vs temporal   verdict
  x_signal                   0.0273       0.0298    no split-driven gap (audit the feature itself)
  x_drifting                -0.0127       0.1770    SPLIT ARTIFACT - the random number is not real
  x_user_mean_global        -0.0070       0.0210    no split-driven gap (audit the feature itself)
  x_user_mean_trainonly      0.1913       0.0324    SPLIT ARTIFACT - the random number is not real

how to read this
  Gaps below about 0.04 sit inside sampling noise at this test-set size, so only the
  two flagged rows below are real artifacts.

  x_signal is stationary and entity-independent, so all three splits roughly agree:
  that is the control proving the dataset and the metric themselves are fine.

  x_drifting collapses under the TEMPORAL split - below 0.5, i.e. actively
  anti-predictive - because its relationship to the label reverses across the time
  axis. A random split averages past and future together and reports a number
  production will never see. This is the leak a temporal split exists to catch.

  x_user_mean_trainonly collapses to ~0.5 under the GROUPED split, because a user
  with no training history gets the fallback constant. That is the honest cold-start
  number. Its higher score under the other splits is legitimate only if you really
  will have that user's history at serving time. This is the leak a grouped split
  exists to catch.

  x_user_mean_global is the important one: it scores high under EVERY split. The leak
  is not in the split, it is in the feature - the aggregate was computed over the
  whole dataset, so each row's own label is inside its own feature value and no
  partition can remove it. A number that is stable across all three splits is
  therefore NOT evidence of validity. Only reading the transformation code, or
  auditing feature timestamps, finds this class of bug.

choose the split that matches how the model will be used - temporal if you predict
the future, grouped if you will see unseen entities, both if both are true - and
compute every aggregate feature from training data only.
