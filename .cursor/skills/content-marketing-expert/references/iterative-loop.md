# The Iterative Loop

Five passes over every piece of content. Each pass ends by naming its own weakest
point; a pass that reports nothing wrong has not looked hard enough. Two full
loops is the normal cost of a good piece — budget for it.

## Pass 1 — Hook

Produce three variants and pick one deliberately.

| Variant | Shape | Works when |
|---------|-------|------------|
| Curiosity | Open a gap the viewer wants closed | The topic is unfamiliar |
| Pain-point | Name the frustration in their words | The audience is already stuck |
| Promise | State the outcome and the cost | The audience is comparing options |

Judge the hook against the first second of video or the first two lines of text —
that is all the viewer gives you. A hook fails if it needs context to make sense,
if it opens with a logo or a greeting, or if it could sit on top of any other
piece of content unchanged.

## Pass 2 — Body

- One idea per beat. If a beat needs "and", split it.
- Concrete before abstract: the example, then the principle.
- For video, every beat gets a visual change — a cut, a graphic, a reframe.
- Cut any sentence that only restates the previous one.

Read the body aloud. Anywhere you stumble is where the viewer scrolls.

## Pass 3 — SEO

Keyword work is research, not invention. Pull terms from real sources — the
platform's own search suggestions, the questions the audience already asks in
comments and support tickets, competing content that ranks. Do not fabricate
search volumes; if a number is not verified, mark it `TBD-verify`.

| Element | Rule |
|---------|------|
| Primary keyword | One per piece. In the title, the first 100 words, and one H2. |
| Secondary keywords | 2-4 supporting terms, placed where they read naturally |
| Title | Under 60 chars, keyword near the front, still a sentence a human would say |
| Meta description | Under 155 chars, written as a promise rather than a summary |
| Alt text | Describes what the image shows and does; keyword only if it fits honestly |
| Headings | H2 per section, phrased as the question the section answers |
| Hashtags | Within the platform cap; specific beats broad |

Placement that hurts: a keyword repeated past the point of natural reading, a
title that reads like a query string, alt text stuffed with terms. Search systems
and humans both penalize this, and the layman-clarity requirement outranks any
keyword target. When they conflict, clarity wins — record the trade in the
equilibrium notes.

## Pass 4 — Call to action

One action per piece. Two calls to action produce fewer of both.

| Goal | Native action |
|------|---------------|
| Reach | Share or send to a friend |
| Saves | "Save this for when you need it" |
| Follows | Show what the next piece will cover |
| Clicks | Link in the reply or the comment, not the primary post |
| Conversions | Name the price and the next step plainly |

Avoid engagement-bait phrasing ("comment YES", "RT if"). Platforms demote it and
audiences discount it.

## Pass 5 — Accessibility

- Captions present and time-aligned.
- On-screen text at or above 4.5:1 contrast, held long enough to read twice.
- Alt text on every image.
- Reading level checked against the audience target.
- No information conveyed by color alone.

## Loop exit

Stop iterating when the hook survives being read cold, the body has no restated
sentences, the SEO package is complete without distorting the copy, the CTA is
singular, and accessibility passes.

**Cap the work at three full loops.** If a tolerance floor in
`ensemble-review.md` is still unmet after the third loop, deliver anyway — but
name the failing player, its score, and the specific line that blocks it in the
equilibrium notes, and state plainly that the piece is not ship-ready. Silently
looping a fourth time is worse than an honest handoff.

Record what changed in each pass in the memory shot's `iteration_log` if the user
opts to save one.
